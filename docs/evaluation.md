# Evaluation

Two kinds of evaluation:

- **Runtime (inside the agent):** grading agents, independent verifiers, coverage checks and two human reviews check every run. See `ARCHITECTURE.md`.
- **Offline (this file):** a fixed set of topics run through the whole real pipeline (`python -m evals.run_eval`), with metrics computed in code. Raw output: [`evals/results.json`](../evals/results.json).

## What is measured

| Metric | How | Status |
| --- | --- | --- |
| Quote provenance | Share of evidence quotes (main relevance, connections, gaps) that are verbatim substrings of the cited paper's own abstract or full text | Measured |
| Grading pass rate | First and final grade per stage, read from each run's trace | Measured (model judgments) |
| Completion, tokens, time | Run status, provider-reported tokens, wall time | Measured |
| Cluster agreement | LLM matcher between our clusters and a survey's section topics, IDs validated in code | Needs an answer key (below) |
| Gap recall | Same matcher against the survey's open problems | Needs an answer key |
| Human support rate | Blind human judgments of connections/gaps and of cluster pairs | Review packs ready, no labels yet |

Cluster agreement and gap recall stay `null` until someone who has read a survey for each topic fills `expected_clusters` / `expected_gaps` in [`evals/topics.yaml`](../evals/topics.yaml). No answer key is generated by a model.

## Results: real runs, 26 October 2026

Three topics at Normal effort (30 papers each), real Nightshift (Nemotron 3 Ultra), OpenAlex + arXiv retrieval, Zetaris paper store, 250k-token budget, 60 s model timeout.

| Topic | Status | Time | Tokens (calls) | Main / side groups | Connections | Gaps | Quotes verbatim | Grades (first → final) |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| LLMs for low-resource languages | partial: provider timeout in connections | 698 s | 187k (50) | 15 / 11 (7 single) | 8 | not reached | 93 / 93 | clusters 6 → 6, connections 6 |
| GNNs in drug discovery | partial: provider timeout in connections | 373 s | 72k (23) | 21 / 5 (4 single) | 7 | not reached | 71 / 71 | clusters 9 |
| Transformers for protein structure | done | 538 s | 231k (55) | 7 / 14 (8 single) | 7 | 0 | 54 / 54 | clusters 3 → 6, connections 6 → 9, gaps 9 |

Summary: quote provenance **218 / 218 (100%)**; 1 of 3 runs completed; first-attempt grading pass rate 2 of 6 stage grades, final pass rate 3 of 6; mean 536 s and 163k tokens per run.

### What the results show

- **Every quote is real.** All 218 evidence quotes are verbatim from the paper they are attributed to. This is guaranteed by construction (models cite span IDs and code copies the text), and the measurement confirms nothing bypasses it. It shows provenance, not that each quote semantically supports its claim; that needs the human reviews.
- **Gaps are rare because the checks work.** In the completed run, 6 gap candidates gave 4 abstentions (no stated open problem) and 2 hypotheses that passed verification but were then removed by the coverage check, because a paper already in the corpus answers them (Uni-Fold for the ManyFold comparison; a joint sequence–structure transformer for the other). Zero reported gaps is an honest outcome, not a missing stage.
- **Cluster grades stay below the pass mark.** The grader repeatedly asks to move broad-but-relevant papers out of the main pool or to merge fragmented side topics (7–8 singletons). The redo does not fix this (6 → 6, 3 → 6), so it costs ~37k tokens per run for little change. Main-pool size varies widely with the question's breadth (7 to 21 of 30 papers).
- **Provider latency caused both partial runs.** Nightshift occasionally took 62–68 s for ~2k-token requests that usually take ~10 s; with the 60 s timeout and one retry, two runs lost the connection stage. Since this evaluation the timeout is 90 s (the rules' upper bound), and a provider failure now returns the finished stages as `partial` (before this change the same timeout crashed the whole evaluation).
- **Time exceeds the target in one case.** 698 s is above the 5–10 minute target; most of it is source-grounded relevance checking and grading.

### Fixed during this evaluation

The first real runs of the evaluation exposed problems that are now fixed and covered by tests:

| Problem found | Fix |
| --- | --- |
| A 50k Normal budget stopped every real run inside clustering; 150k stopped inside the connection redo | Budgets 250k / 450k / 700k / 1M from measured usage |
| A Nightshift timeout raised out of `/run` and discarded all finished stages | Provider failures after Human review 1 return `partial` |
| The grader once returned 0/0/0 with empty reasoning, triggering a costly redo | Grades must include reasoning, and a fix when failing; repaired once otherwise |
| An empty gap list scored 0/9 in one run and 9/9 in another | Empty outputs are graded as abstentions, explicitly |
| Sample-mode placeholders quoted titles when a paper had no abstract | Placeholders quote abstracts only |

## Reproduce

```bash
python -m evals.run_eval --sample-mode   # harness check, offline
python -m evals.run_eval                  # real: Nightshift, OpenAlex/arXiv, Zetaris; ~10 min and ~200k tokens per topic
python -m evals.run_eval --only gnn-drug  # one topic
```
